# Infrastructure and Platform Configuration

**API Group**: `config.openshift.io/v1`
**Kind**: `Infrastructure` (singleton: `cluster`)
**Scope**: Cluster

## Purpose

The `Infrastructure` CR is the single source of truth for platform type and topology in an OpenShift cluster. CCCMO reads it at every reconcile to decide which cloud provider assets to deploy, which cloud config transformer to apply, and whether the cluster is single-replica or multi-replica. CCCMO does not own this resource — it is created by the OpenShift installer and updated by the platform.

**Key Principle**: CCCMO is entirely stateless with respect to platform selection — it derives all platform decisions from `Infrastructure.Status.PlatformStatus.Type` at reconcile time.

## Spec Structure (relevant fields)

```go
// Infrastructure.Spec (fields CCCMO reads)
type InfrastructureSpec struct {
    // CloudConfig is a reference to a ConfigMap in openshift-config
    // containing the source cloud config (e.g., cloud.conf for OpenStack).
    CloudConfig ConfigMapFileReference
}

// Infrastructure.Status (fields CCCMO reads)
type InfrastructureStatus struct {
    // PlatformStatus contains cloud provider-specific status.
    PlatformStatus *PlatformStatus

    // InfrastructureName is a short unique identifier for the cluster,
    // used to label CCM Deployments and PodDisruptionBudgets.
    InfrastructureName string

    // ControlPlaneTopology is SingleReplica or HighlyAvailable.
    // Drives IsSingleReplica in OperatorConfig.
    ControlPlaneTopology TopologyMode
}

type PlatformStatus struct {
    // Type is the platform type (AWS, Azure, GCP, OpenStack, VSphere, etc.)
    Type PlatformType
    // Platform-specific status structs (e.g., AWSStatus, AzureStatus)
    AWS       *AWSPlatformStatus
    Azure     *AzurePlatformStatus
    // ...
}
```

## Key Concepts

### Platform Detection

`pkg/cloud/cloud.go` contains the authoritative `switch` on `PlatformStatus.Type`. Every new platform must be registered here in two functions:

- `getAssetsConstructor()` — maps platform type to `NewProviderAssets` constructor
- `GetCloudConfigTransformer()` — maps platform type to ConfigMap transformer function

### Cloud Config Source and Sync

`Infrastructure.Spec.CloudConfig` optionally references a source ConfigMap in `openshift-config`. The `CloudConfigReconciler` checks this field to decide if a sync from the cluster operator's managed namespace is needed.

For AWS and Azure the config is currently generated by the Cloud Credentials Operator (CCO) into `openshift-config-managed/kube-cloud-config`. CCCMO reads from there and applies its transformer, then writes to `openshift-cloud-controller-manager/cloud-conf`.

### Single vs. Multi-Replica

`InfrastructureStatus.ControlPlaneTopology` determines `OperatorConfig.IsSingleReplica`. When true, CCCMO skips creating `PodDisruptionBudgets` for CCM deployments.

### External Platform Guard

If `PlatformStatus.Type == External`, CCCMO exits the reconcile loop early and reports `Available=true`. This allows clusters without built-in cloud support to coexist with CCCMO.

### Provisioning Gate: CloudControllerOwnership

Before applying CCM manifests, `CloudOperatorReconciler` checks:
1. That all sub-controller conditions (CloudConfig, TrustedCABundle) are `Available`
2. That the `ExternalCloudProvider` feature gate is enabled (until full GA)
3. That the cluster already has CCM ownership (`cloudControllerOwnershipCondition`)

## Lifecycle

1. **Cluster Install**: Installer creates `Infrastructure/cluster`. CCCMO reads it and deploys the appropriate CCM DaemonSet/Deployment.
2. **Upgrade**: CVO delivers new CCCMO image. Reconcile re-reads Infrastructure, re-renders templates with updated images, applies changes.
3. **Platform Change**: Not supported. Platform type is immutable post-install.

## Example

```yaml
apiVersion: config.openshift.io/v1
kind: Infrastructure
metadata:
  name: cluster
spec:
  cloudConfig:
    key: cloud.conf
    name: cloud-provider-config    # in openshift-config namespace
status:
  infrastructureName: my-cluster-abc12
  controlPlaneTopology: HighlyAvailable
  platformStatus:
    type: OpenStack
    openstack:
      cloudName: openstack
```

**Use case**: CCCMO detects `OpenStack`, calls `openstack.NewProviderAssets`, applies the OpenStack CCM Deployment, and syncs the cloud-conf ConfigMap using `openstack.CloudConfigTransformer`.

## Component-Specific Behavior

- CCCMO uses `configv1.Infrastructure` from `github.com/openshift/api/config/v1`; it does not define its own CRD for platform selection.
- The `kube-cloud-config` name in `openshift-config-managed` is a hard-coded constant (`managedCloudConfigMapName`) — it is the CCO-managed output.
- The destination ConfigMap written by CCCMO is `openshift-cloud-controller-manager/cloud-conf` (constant `syncedCloudConfigMapName`).
